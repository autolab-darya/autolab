# AutoLab — учебный сайт для «Веб-аналитики»

**Версия:** 1.0, октябрь 2026 г.  
**Формат:** статический HTML/CSS/JavaScript без серверной части.  
**Совместимость:** настольные и мобильные браузеры, GitHub Pages.

## Что находится внутри

- `index.html` — главная страница;
- `structure.html` — устройство автомобиля: 7 переключаемых автомобильных систем;
- `service.html` — обслуживание: 5 тематических вкладок и чек-лист;
- `glossary.html` — автословарь из 25 терминов, фильтр по буквам и поиск;
- `quiz.html` — интерактивный тест из 10 вопросов с подсчётом результата;
- `about.html` — описание проекта, кнопка «Поделиться», сведения о статистике;
- `css/style.css` — дизайн для компьютеров и телефонов;
- `js/main.js` — функции страниц и единая система событий;
- `assets/` — локальные иллюстрации и иконка.

Никакие внешние библиотеки для работы сайта не требуются. Все ссылки на страницы и файлы **относительные**, поэтому сайт подходит для размещения в подпапке на GitHub Pages (`/autolab/`).

## Шаг 1. Посмотреть на Mac

1. Распакуй ZIP-архив и открой папку `AutoLab_site`.
2. Для предварительного просмотра открой `index.html` в браузере.
3. Удобнее запускать из терминала macOS, чтобы проверить сайт в режиме локального сервера:

   ```bash
   cd ~/Downloads/AutoLab_site
   python3 -m http.server 8000
   ```

   После этого открой `http://localhost:8000/`.

Если распаковала архив в другую папку, укажи **свой** путь вместо `~/Downloads/AutoLab_site`. Остановить локальный сервер можно сочетанием `Control+C` в терминале.

Это локальный адрес, он **не подходит для сбора посещений людей из интернета**.

## Шаг 2. Разместить в интернете на GitHub Pages

1. Войди на [github.com](https://github.com/) или создай учётную запись.
2. Создай **публичный** репозиторий, например `autolab` (Repository → New).
3. Загрузить нужно **содержимое распакованной папки**, а не сам ZIP-файл: 6 HTML-страниц, папки `assets`, `css`, `js` и этот `README.md`.
4. Убедись, что `index.html` расположен в корне репозитория.
5. Открой **Settings → Pages**. В блоке **Build and deployment** выбери **Deploy from a branch**, ветку `main`, папку `/(root)` и сохрани.
6. После успешной публикации появится ссылка вида `https://ИМЯ-ПОЛЬЗОВАТЕЛЯ.github.io/autolab/`.
7. Проверь главную страницу, ссылки на все разделы, поиск и тест. Открой опубликованную ссылку с телефона.

*Внешний вид интерфейса GitHub может меняться. Если браузер не загрузит папки при перетаскивании, можно использовать GitHub Desktop или команды Git. ZIP нельзя просто разместить в репозитории как единственный файл: GitHub Pages не распаковывает его автоматически.*

**Важно:** сейчас сайт написан и протестирован локально, но он **не опубликован**; публичная ссылка появится только после размещения из твоего аккаунта.

## Шаг 3. Подключить счётчики (для лабораторных № 3, 4 и 5)

В исходном ZIP **нет подключённых счётчиков и нет выдуманных ID**. В HTML оставлены специальные комментарии `МЕСТО ДЛЯ СЧЁТЧИКОВ` (в `<head>`) и `СЧЁТЧИКИ С ВИДЖЕТОМ` (у нижней части страницы).

После регистрации каждого сервиса нужно:

1. Внести опубликованный URL сайта в кабинет сервиса.
2. Получить **реальный код** счётчика LiveInternet / Rambler Top100 / веб-аналитики Mail.ru–MyTracker по методичке.
3. Установить код **на каждую из шести страниц** (или вынести подключение в единый JS-файл, если это разрешено инструкцией сервиса).
4. Если методичка требует видимый виджет — вывести реальный виджет в подвал каждой страницы. Не заменять его декоративной картинкой.
5. Проверить в браузере отсутствие ошибок, а в личном кабинете — корректный статус и поступление **реальных** данных. Учти возможную задержку обновления статистики.
6. Сделать скриншоты реальных настроек и результатов для отчётов.

Для лабораторной № 4 предусмотрены возможные события `quiz_started` / `quiz_completed`; для № 5 как цели можно рассмотреть `quiz_completed` и `checklist_completed` (окончательный выбор зависит от поддерживаемых инструментом типов целей). Сопоставление с конкретными SDK производится **после получения ID и проверки актуальной документации**.

### Уже предусмотренные события интерфейса

Когда посетитель выполняет действие, `js/main.js` создаёт событие браузера `autolab:analytics`. В поле `detail` указано название действия и необязательные параметры. Например:

| Событие | Что означает |
|---|---|
| `quiz_started` | Пользователь нажал «Начать тест» |
| `quiz_completed` | Пользователь закончил 10 вопросов; в параметрах есть баллы |
| `glossary_search` | Пользователь ввёл запрос в словаре (текст запроса **не передаётся**) |
| `glossary_term_view` | Пользователь выбрал карточку термина |
| `checklist_completed` | Пользователь отметил все 5 пунктов чек-листа |
| `view_vehicle_system` | Пользователь открыл конкретную автомобильную систему |
| `site_shared` | Браузер подтвердил отправку или копирование ссылки |

Остальные кнопки также имеют событийные метки `data-track`. Наличие таких событий **не означает**, что какая-либо система веб-аналитики уже получила данные — для этого требуется установить её официальный код/SDK.

Чтобы посмотреть события локально, открой, например, `http://localhost:8000/quiz.html?debug=1` и открой консоль разработчика. Затем пройди тест. Появятся записи `[AutoLab event]`.

## Шаг 4. Набрать аудиторию и оформить лабораторные

- Отправь **опубликованную** ссылку одногруппникам и внеси её в общую таблицу.
- Собирай посещения согласно методичкам (период 1–2 недели, не менее 50 пользователей, если это именно требование соответствующей работы).
- **Пользователи, визиты и просмотры страниц — разные метрики.** Не заменяй требуемых уникальных посетителей количеством переходов.
- Получай реальные данные в кабинетах каждого сервиса, а не по внешнему виду страницы.
- Для отчётов сделай аккуратные скриншоты страниц и кабинетов статистики, запиши период, метрики, метод измерения и выводы.
- Не используй искусственные сервисы накрутки: их трафик может отфильтровываться, противоречить правилам аналитики или условиям проверки преподавателя.

## Проверка функций перед сдачей

- [ ] Все шесть страниц открываются и переходы в меню работают.
- [ ] В мобильной версии меню открывается и закрывается.
- [ ] На странице «Устройство» переключаются все 7 вкладок.
- [ ] На странице «Обслуживание» работают 5 вкладок, чек-лист и кнопка сброса.
- [ ] В автословаре работает поиск, фильтрация и карточки терминов.
- [ ] Тест из 10 вопросов завершается и показывает результат.
- [ ] После публикации сайт открывается с мобильного интернета.
- [ ] Каждый счётчик установлен **с личным ID**, проверен и данные поступают.
- [ ] Скриншоты и отчёты отражают реальные действия и статистику.

## Приватность

Чек-лист сохраняется в `localStorage` только на устройстве посетителя. Тексты поисковых запросов не отправляются внутренним обработчиком событий. До подключения кодов сторонних систем аналитики сайт сам ничего им не передаёт. После подключения счётчиков обнови описание обработки данных на странице «О проекте» и при необходимости добавь механизм согласия на cookies в зависимости от применимых правил и используемых сервисов.

**Содержимое — учебно-справочное.** Советы по обслуживанию не заменяют регламент производителя и диагностику специалиста. Медиафайлы предназначены для этого учебного сайта.
